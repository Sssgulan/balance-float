# balance-float / OCX 指标 接口说明

> 打包日期：2026-09-20。前端保留收起态、展开态、接入页三个窗口状态，本文说明后端接口与启动方式。

## 1. 工程结构

```
balance-float/
  float_window.py      # 悬浮窗壳 + 本机 HTTP API（主入口）
  ocx_metrics.py       # OCX 端口合计指标（读 usage.jsonl）
  providers.py         # 各类型余额/流量适配
  configs/             # 账户与设置（分文件）
  pages.py             # 页面组装：把 ui/parts/ 的片段拼成整页（由本机 HTTP 服务实时调用）
  theme.py             # 主题变量表：颜色 / 尺寸 / 动效的单一来源
  ui/index.tpl.html    # 页面骨架，用 <!--#include:parts/xxx.html--> 引片段
  ui/parts/            # 片段：head / collapsed / expanded / modal / page + js/*.js（按功能分文件）
  ui/theme.json        # 变量值：改这里 = 全站生效，刷新页面即可，不用重启浮窗
  ui/index.html        # 组装产物（便于直接查看；程序实际走 pages.render()，改了片段请重跑）
  test_ui_page.py      # 接入页自检（静态；--live 走 Chrome 端到端）
  test_pages.py        # 组装自检：片段拼回去必须与拆分前的快照逐字节一致
  demo_page.py         # 接入页 demo：本机起服务 + 浏览器点（--real 用真实 configs/）
  demo_ccsw.py         # CC-SW 参数确认 / 导入 / 启用
  demo_sync.py         # OCX+CC-SW 同步 demo
  test_backend.py      # 后端自检（安全/线程/导入，无框架）
  probe_ocx_header.py  # OCX 用量 HTTP 探测（核对鉴权头，排查用）
  probe_ocx_usage_nested.py  # OCX usage.jsonl 字段结构探测（排查用）
  make_vendor.py       # 生成 ui/vendor/ 离线字体资源（换字体时才跑）
  make_logo.py         # 生成 assets/logo.png 与 assets/icon.ico
  build_release.py     # 打包成可分发的绿色版
  启动悬浮窗.vbs        # 桌面浮窗启动
```

配置的合并加载与必填校验（原 `main.py`）已并入 `float_window.py`（`load_config` / `REQUIRED_FIELDS` / `_check`），
后端只剩一份配置口径。

预览页（随包或本机工作目录）：

```
index.html             # OCX 单端口指标曲线预览
serve_ocx_demo.py      # 本地预览服务（默认 8799）
```

## 2. 启动方式

| 场景 | 命令 |
|------|------|
| 桌面浮窗 | 双击 `启动悬浮窗.vbs` → `pythonw float_window.py`，监听 `127.0.0.1:8765` |
| OCX 指标预览 | `python serve_ocx_demo.py` → `http://127.0.0.1:8799/` |
| 配置校验 | `python -X utf8 float_window.py --check`（不弹窗，只打印合并后的必填校验） |
| CC-SW 确认 | `python demo_ccsw.py`（`--import` / `--balance 名称` / `--fetch`） |
| 后端自检 | `python -X utf8 test_backend.py`（临时目录，不碰真实 configs/） |
| 接入页自检 | `python -X utf8 test_ui_page.py`；加 `--live` 走 Chrome 端到端 |

浮窗端口被占用时会向后顺延（8765–8775），以实际提示为准。

## 3. 安全约定

- 仅监听 `127.0.0.1`（本机）。
- GET：校验 `Origin` 为 `http://127.0.0.1:<port>`（无 Origin 的 curl 放行）。
- POST：需 `Content-Type: application/json` + `X-Api-Token`。
  - 令牌在 `index.html` 的 `<meta name="api-token">` 注入；
  - 也可在 pywebview 里 `Bridge.get_api_token()` 取得。
- `/api/accounts` 凭据字段掩码化（`••••` + 末 4 位）。
- OCX 余额若开启，凭据查询时只读 CC Switch/本地配置，**不写入** ccsw.json。

## 4. 通用账户接口（浮窗 8765）

### GET

| 路径 | 返回 |
|------|------|
| `/api/state` | `{stations, traffic, loading, updated, accounts, settings}` |
| `/api/accounts` | 全部账户（含未启用）+ `enabled` + `file`，凭据掩码 |
| `/api/ccsw/scan?local=1` | CC Switch 节点清单 + 有用/无用参数 + 是否已导入 |
| `/api/ccsw/review` | 参数确认清单（供勾选启用） |
| `/api/ocx/scan?probe=1` | OCX 配置扫描（`probe=1` 才测代理） |
| `/api/ocx/metrics` | **OCX 单端口合计指标**（见第 5 节） |
| `/api/ocx/metrics/config` | 指标轮询配置 |
| `/api/generic/presets` | generic 三条内置模板 |
| `/api/official/models` | 主流模型清单 + 标准字段表（`configs/official/models.json` 原样返回） |

### POST（需 `X-Api-Token`）

| 路径 | 入参 | 说明 |
|------|------|------|
| `/api/account/save` | `{account:{...}}` | 带 id 原位更新；掩码/空凭据 = 未改 |
| `/api/account/delete` | `{id}` 或 `{ids:[...]}` | 删除并清理 order，同时把该节点写进忽略名单（见下）。接入页的批量删除走 `{ids}`：一个请求里**持锁**删完整批再落盘；旧调用方仍可只传 `{id}` |
| 返回 | `{ok, results:{id:{ok,error?}}}` | 传 `ids` 时逐条回执在 `results`；传单个 `id` 时仍是原来的 `{ok,error?}` |
| `/api/account/reorder` | `{ids:[...]}` | 全局显示顺序 |
| `/api/account/test` | `{account, timeout?}` | 转 providers；test 凭据可暂缺 |
| `/api/settings` | `{refresh_seconds 或 refresh_minutes, timeout}` | 白名单三键 |
| `/api/official/models/save` | `{key, fields}` | 只覆盖该模型在 json 里已声明的键 |
| `/api/ccsw/import` | `{provider_ids?, enabled?, features?}` | 选择性导入 CC-SW |
| `/api/ccsw/update` | `{id 或 provider_id, enabled, features, name?}` | 显示/隐藏、开流量/余额 |
| `/api/ocx/import` | `{probe?}` | 按配置导入 OCX，不要求代理在线 |
| `/api/ocx/import_path` | `{path, probe?}` | 手动指定配置文件 |
| `/api/ocx/import_checked` | `{path, probe?}` | 从 `/api/ocx/scan` 的 `checked` 候选里挑一条（不接受任意路径） |
| `/api/ocx/ccsw_sync` | `{probe?}` | 一次跑完 OCX+CC-SW 扫描/导入/流量匹配 |
| `/api/ocx/metrics/config` | `{interval_seconds, window_seconds, enabled}` | **调节指标轮询** |

### CC-SW 账户落盘字段（有用）

`id, name, type=ccsw, provider_id, base_url, app_type, enabled, features, balance_kind`

- `features`: `["traffic"]` 或 `["traffic","balance"]`
- `enabled=false`：不进 `/api/state`、不参与刷新
- 扫描期无用字段（不落盘）：`is_local, has_token, usage_script, accessToken, userId, meta` 等

### OCX 与 API key

- 代理：`http://127.0.0.1:10100/v1`（或 `localhost`）
- 模型列表：`GET /v1/models`（Bearer 或专用头均可）
- 目录：`GET /v1/catalog`
- 用量 HTTP：`GET /v1/usage` 需头 **`x-opencodex-api-key: ocx_data_...`**，且实例 `runtimeRole=hub`；本机 standalone 会返回 `hub_usage_not_a_hub`
- **今日 token/延迟请走本包 `ocx_metrics`（读 `~/.opencodex/usage.jsonl`）**，不必打 OCX 用量 HTTP

## 5. OCX 指标接口（重点）

数据源：`%USERPROFILE%\.opencodex\usage.jsonl`（本地账本，**不高频请求 OCX**）。

### GET `/api/ocx/metrics`

浮窗：`http://127.0.0.1:8765/api/ocx/metrics`  
预览服务：`http://127.0.0.1:8799/api/ocx/metrics`

```json
{
  "ok": true,
  "endpoint": "http://127.0.0.1:10100",
  "day": "2026-09-20",
  "today": {
    "requests": 403,
    "ok_requests": 364,
    "tokens_total": 22923537,
    "tokens_input": 22365018,
    "tokens_output": 558519,
    "cache_read_tokens": 20172288,
    "avg_latency_ms": 19548.7,
    "avg_ttft_ms": 3591.9
  },
  "speed": {
    "window_seconds": 30,
    "interval_seconds": 3,
    "current_out_tok_per_s": 0,
    "points": [
      {"ts": 1789..., "t": "14:02:01", "output_tokens": 0, "out_tok_per_s": 0, "requests": 0}
    ]
  },
  "config": { "interval_seconds": 3, "window_seconds": 30, "enabled": true }
}
```

- **不按模型分类**，整端口合计。
- `speed.points` 为滚动窗口（默认 30s）内每次采样点，过期自动删除。
- 曲线用途：`out_tok_per_s` 随时间变化 = 输出 token 速度。

### POST `/api/ocx/metrics/config`

```json
{
  "interval_seconds": 3,
  "window_seconds": 30,
  "enabled": true
}
```

| 字段 | 范围 | 含义 |
|------|------|------|
| `interval_seconds` | 1–60 | 读账本间隔（秒），可调以免负担 |
| `window_seconds` | 10–120 | 速度曲线保留窗口 |
| `enabled` | bool | 关闭则停止采样 |

- 预览服务 `serve_ocx_demo.py`：本机 POST **免 token**。
- 浮窗 8765：POST 需 **`X-Api-Token`**。

## 7. 前端接入页（已接后台）

展开态底部“添加”进入接入页（由 `ui/parts/page.html` 组装出的第三个窗口状态）。卡片沿用模板配置弹窗的尺寸
（宽 360、高 420），尺寸按卡片上报，不跟随收起/展开态；页签即账户类型：
官方接口 / NewAPI / 自定义（`generic`）/ CC-SW / OCX，**默认停在官方接口**。

官方接口页签从上到下：常用服务商选块（DeepSeek / Kimi / GLM，只需填 API Key）→ 主流模型清单（按分类分组，
点一行进该模型的标准字段页）→ 底部新增按钮。模型的字段表在后端 `configs/official/models.json`：
`fields` 给每个标准字段的标题/提示/图标，`models` 里每个模型用 `key` 认领自己要哪几个字段，
页面按这个顺序铺成「标题行 + 输入行」，值留空自己填；加模型/加字段只改这个 json。该文件不参与账户扫描。

自定义页签给一个 JSON 文本框，键名以后端为准（`name`、`url`、`api_key`、`timeout`、`headers`、`json_paths`）；
列表最下方的页脚固定在滚动区之外，放“导入刷新”气泡与“一键删除”；CC-SW 没有“新增”，OCX 则留着“新增 OCX”，表单是「名称 + 服务器连接 + API 密钥」（服务器连接必填，密钥可留空，落盘 configs/ocx.json）：
一键删除沿用展开页减号的交互（进入删除模式 → 行尾圆圈勾选 → 确认），走 `POST /api/account/delete`，不弹系统确认框。

| 操作 | 接口 |
|------|------|
| 进入页签、列出该类型账户 | `GET /api/accounts`（凭据掩码） |
| 新增 / 点行编辑回填 | 掩码值原样回传 = 未改动，后端沿用原值 |
| 测试连接 | `POST /api/account/test`（凭据可暂缺） |
| 保存并启用 | `POST /api/account/save` |
| 删除 | `POST /api/account/delete` |
| 轮询间隔 / 超时 | `POST /api/settings`（传分钟或秒，落盘仍为秒） |
| 主流模型清单 / 保存标准字段 | `GET /api/official/models` · `POST /api/official/models/save` |
| 返回列表 / 刷新 | `GET /api/accounts` + `GET /api/state` |

余额、流量与启用状态仍由 `GET /api/state` 驱动，接入页只做账户的增删改，不重复拉余额。

已接的“导入刷新”：

1. CC-SW：`GET /api/ccsw/scan` 确认 `cc-switch.db` → `POST /api/ccsw/import {}`（全部可导入项，`features` 默认 `["traffic"]`）
2. OCX：`POST /api/ocx/import {probe:false}`（只读配置，不要求代理在线；`ocx/import_path`、`ocx/import_checked` 留给手动指定路径）；`POST /api/ocx/ccsw_sync` 里再跑一遍 `ocx_import_configured`，把手填节点按地址探一次并回写 `last_count`

未接（页签已在、按钮未挂，接口已就绪）：

1. 指标曲线：前端定时 `GET /api/ocx/metrics`（建议 ≥ 2s）画 `speed.points`；调参走 `POST /api/ocx/metrics/config`，**不要**用前端死循环打 OCX `/v1`
